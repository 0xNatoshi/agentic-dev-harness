The user reports repositories on v5.1/v5.2. Their authentic template snapshots are not in this package. Do not relabel v5/v6 files or reconstruct those snapshots from version numbers. Preserve any authentic v5.1/v5.2 history already installed on the destination PC; verify provenance and content, then carry those snapshots and their index entries into a staged skill directory before replacement. If provenance cannot be verified, retain the files separately in the backup and report that the historical base is unqualified. When migrating a repository without an authenticated historical base, preserve a repository-specific capture and its local safeguards as described in `../../references/adoption-and-licenses.md`.

Historical content may use old personal wording or review policy. It remains immutable comparison evidence and is not the current policy. Keep the index sorted by version. The current v6.3 snapshot must match the active template byte for byte at release; do not modify it after release.
